# Languages (i18n)

NodeDesk ships in **English** (the source language) and **Portuguese (Brazil)**. The language is chosen in *Settings → General → Language*: *Auto* follows the browser (`navigator.languages`), and the choice is stored in SQLite so it follows you across browsers. Dates, times and numbers use the matching locale (`en-US` / `pt-BR`), so Portuguese gets decimal commas and the 24-hour clock unless you choose otherwise.

## How it works

- `frontend/src/i18n/en.ts` holds every UI string as a flat, dotted key (`files.new_folder`). It is the source of truth.
- `frontend/src/i18n/pt.ts` is typed `Record<Key, string>`, so **a missing or extra key fails `tsc`**. There is no way to ship a half-translated language by accident.
- Code calls `t("key", { param })`. Placeholders are `{name}`; plurals use the `_one` / `_other` suffix and a numeric `count` (`t("files.items", { count: 3 })`).
- Strings are resolved when rendered, so changing the language remounts the UI (window contents are re-created; open windows stay open).
- Things that are defined at module level (app titles, widget names, setting labels) use **getters** (`get title() { return t("app.files") }`) so they follow the current language.

## Backend messages

API errors are written in English at the call site. The server looks at `Accept-Language` (the UI sends its current language) and, for Portuguese, renders the message from `backend/internal/httpx/i18n.go`, keyed by the English format string. A message without a translation falls back to English, so nothing is ever hidden. The audit log and server logs stay in English on purpose.

## Adding a language

1. Add its code to `Lang` and `LANGUAGES` in `frontend/src/i18n/index.ts` (and to `resolveLang`, `locale()`), and to the allowed values of the `language` setting in `backend/internal/api/settings.go`.
2. Copy `pt.ts` to `xx.ts`, translate the values, register it in `dictionaries`.
3. Optionally add a catalog like `catalogPT` in `httpx/i18n.go` for API errors.
4. `pnpm typecheck` tells you if a key is missing.

## Writing new UI text

Never hard-code user-visible text. Add the key to `en.ts` **and** `pt.ts` in the same commit, then use `t()`. Keep sentences whole (use placeholders instead of concatenating fragments) so word order can differ between languages.
